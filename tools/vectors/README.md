# Golden vectors

Test vectors for the C# port, generated by calling the Python reference (KalshiTerm2) as the oracle.
The generated JSON is committed under `tests/KalTerm.Core.Tests/Vectors/`; CI reads it and never runs
Python. Regenerate only when the reference changes, review the diff, and record the reference commit
(the generator writes it into each file).

```powershell
python tools/vectors/generate_fixedpoint.py --reference %USERPROFILE%\dev\KalshiTerm2
python tools/vectors/generate_fees.py --reference %USERPROFILE%\dev\KalshiTerm2
python tools/vectors/generate_ratelimit.py --reference %USERPROFILE%\dev\KalshiTerm2
python tools/vectors/generate_config.py --reference %USERPROFILE%\dev\KalshiTerm2
python tools/vectors/generate_ed25519.py --reference %USERPROFILE%\dev\KalshiTerm2
python tools/vectors/generate_clock.py --reference %USERPROFILE%\dev\KalshiTerm2
python tools/vectors/generate_models.py --reference %USERPROFILE%\dev\KalshiTerm2    # needs: pip install pydantic
python tools/vectors/generate_api_format.py --reference %USERPROFILE%\dev\KalshiTerm2
python tools/vectors/generate_orderbook.py --reference %USERPROFILE%\dev\KalshiTerm2   # needs the reference's dependencies, see below
```

`generate_models.py` runs the reference's pydantic models over an adversarial corpus (JSON numbers where strings are
expected, empty strings, nulls, finer-than-scale values, odd date-times, pydantic's lax type coercions) and records
each outcome. The port is stricter than pydantic's coercing mode; each such case carries `port: "error"` and a `why`, so
every deliberate difference is data. Case names are unique (an assertion enforces it) and tell `1` from `"1"`.

`generate_clock.py` imports the reference `clock.py` directly (standard library only). It drops generated cases
where float noise could legitimately flip a status or tip a two-decimal rounding tie, and records the count
(`dropped`) in the file; choose round-trip times that avoid ties, or whole families of cases vanish.

`generate_ed25519.py` is the one generator that needs a third-party package: `cryptography` (`pip install
cryptography`), because the reference signs with it. Use a throwaway venv outside the repo. It runs the
reference's real `load_private_key` and `KalshiSigner.headers()` as the oracle, and reproduces the 21 signing
vectors of spike S-3 exactly.

`generate_api_format.py` loads the reference server's `api/format.py` by path (standard library plus `kalshi_core.fixedpoint`): the decimal strings for prices and counts, the ISO-8601 time text and the opaque cursors the API sends. Its vectors go to `tests/KalTerm.Contracts.Tests/Vectors/`. The reference's cursor decoder also accepts the standard base64 alphabet (`+`, `/`); KalTerm's does not, and the generator leaves those inputs out.

`generate_orderbook.py` replays scripted message streams (25 scenarios: gaps, resets, negative quantities, removed markets, interleaved subscriptions, a REST snapshot) through the reference `kalshi_core.orderbook.BookTracker` and records, after every step, the events it returned, every book it holds and the stale set; the .NET `BookTracker` must reproduce all of it. Importing that module pulls in the reference's own dependencies (`pip install pydantic pydantic-settings cryptography httpx websockets` in a throwaway venv outside the repo). Its vectors go to `tests/KalTerm.Kalshi.Tests/Vectors/`.

`generate_config.py` reads the reference `config.py` statically with `ast` (it cannot be imported without
pydantic): the URL maps, field defaults, constraints and variable prefix come from the source itself.
Vectors are written into the project that tests the code (`tests/<project>/Vectors/`).

`common.py` holds what the generators share (loading `kalshi_core.<module>` from the clone, the
reference commit, writing the JSON). Expectation strings: an integer, `refuse` (outside the domain),
or `overflow` (the reference's unbounded integer does not fit a signed 64-bit long).

Requirements: Python 3.11+ and the standard library only, except `generate_ed25519.py` (`cryptography`) and
`generate_models.py` and `generate_ws_models.py` (`pydantic`), both dev-only in a throwaway venv. The reference clone is read, never edited.

Where the C# port is deliberately stricter or different from the reference, the vector says so
(`csharp` or `unsupported`), so every deviation is visible in the data rather than hidden in a test.
